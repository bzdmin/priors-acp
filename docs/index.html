An agent that predicts before it hires, and remembers when it was wrong.

Priors is a buyer agent on Virtuals Protocol ACP. Before hiring anyone it writes down what it expects to happen, then reads back what actually did. What it learns lives in Sibyl Memory. Delete that memory and it demonstrably behaves differently.

The deletion test

Same code. Same provider. Same claim. Different memory.

A provider declared itself available 24 times across two sessions. Twice it delivered. Sixteen times it went silent and let the job expire. Priors was then asked to hire it once more, twice over: with its memory intact, and with that memory deleted and nothing else changed.

Rules-v2 returned 0.7947 on both runs. Only the memory differed.

Why the bar is not a tuned constant. The bar is 0.4669, which is the marketplace response rate itself: 35,179 of 75,340 created jobs ever reached a provider response. A counterparty Priors has never met sits exactly on the bar and passes, because an unknown agent is treated as typical rather than suspect. That is why the deleted run passes by construction rather than by a number chosen to make it pass.

Reliability moved only as evidence arrived: 0.4669 → 0.5556 → 0.4757 → 0.4160 → 0.1666 across 18 observations. It crossed the bar on the third, not the first, because one broken promise against one kept promise is not yet evidence.

There is no transaction for the refused job, and that is the result. Running with memory intact, Priors refused to create the job at all. Nothing was signed and nothing was spent, so on chain there is simply no job where that one would have been. The absence is the evidence.

Total spend across every live job: 0.03 USDC. A job nobody answers is never funded, so sixteen broken promises cost sponsored gas and nothing else. Evidence decays by half a day, so this figure is quoted at block 51,120,396 and climbs back toward the bar as it ages: 0.2170 on Sep 11, 0.2860 on Sep 12, expiring Sep 15.

Why the gate exists
40,161
of 75,340 ACP jobs never get a provider response at all

The marketplace's largest failure is silence, not bad work.

Across every ACP job on Base from block 44,429,969 to 50,749,122, 75,340 jobs were created and only 18,367 were ever funded. Of the 56,973 that died, 40,161 never drew a provider response of any kind, not rejected, just never answered. The other 16,812 got an answer but never reached funding.

Predicting whether a job will complete does nothing about that. So Priors asks the provider whether it can actually take the work, then weighs that answer against its own record of whether the same provider's earlier answers held up.

A provider response here means a BudgetSet event, the provider-side response step in the ACP SDK. The event carries no setter address, so this is a response rate and is not presented as an acceptance or silence rate.

At scale

187 decisions changed across 18,360 resolved jobs.

The live jobs show that the decision depends on memory. This shows what memory is worth over the whole history. Both runs are the same binary, and the deleted run is never handicapped to flatter the other.

126 right, 61 wrong. Nearly all of them share one shape: memory overruling a hire that the public chain record endorsed, on a job that then failed.

The aggregate movement is small, and pretending otherwise would be dishonest. Accuracy moves from 0.9000 to 0.9035. The reason is that chain evidence alone is already strong: per-provider completion rates with no memory at all reach 90%. Most of those 18,360 jobs are easy calls that drown out the hard ones in any average.

The defensible claim is the reversal count, not the average. 187 of 18,360 is 1% of decisions, and a judge is entitled to weigh it accordingly.

Stage 1

Chain evidence

Per-provider completion rates, shrunk toward the market base rate so a provider with 3 jobs is not read like one with 300. Public data. Works with memory deleted.

Stage 2

Rules from its own errors

Mined from Priors' own resolved mistakes. The lifecycle runs pattern, provisional, then graduated or demoted. Each rule applies only to jobs funded after the evidence that formed it.

Stage 3

Calibration

Priors' record of how its own confidence has held up. Measured, kept, and deliberately not allowed to move the decision.

Nobody can write the record that judges their own claim. Priors writes decisions and requests, the resolver writes episodes and observations, and the counterparty can only declare. That separation is enforced by the API surface itself and pinned by tests.

What Priors refuses to do

Two mechanisms were built, measured, and switched off.

Both would have made memory look more load-bearing. Both were wrong on the evidence, so neither is allowed to act. The code for both is still in the repo, defaulted off.

Rejected

Calibration as an input

Applying it flipped 458 decisions and was right on 45% of them, worse than chance. It is a band-wide average applied to individual jobs, and with the hire bar at 0.5 a correct average nudge pushes fine jobs across the line. Kept as self-knowledge, kept out of the call.

Rejected

A learned hire threshold

Built under the same temporal separation as rules. Every bar above 0.5 scored worse against the real outcome distribution. A threshold is not a learnable fact but a policy choice needing a stated cost model, and inventing one that made the numbers work would be fitting to the replay.

Kept

Rules

187 decisions changed at 67.4%, across 13 providers. Priors changes its behaviour only when its own evidence earns that right.

Honest disclosures

What this is not.

This is a backtest, and is described as one. Every prediction was written before its outcome was read, and that ordering is structurally enforced rather than merely promised. But the historical runs were made in fast-forward against scanned data, not accumulated over months of live trading. The live jobs are the exception and are labelled as such.

Self-dealing. The provider in the live demonstration is Digest, an agent I also operate. Both sides are mine. It exists so the hiring path can be exercised end to end, and it is not counted as independent evidence of anything.

Prior work. The ACP scanner and the dataset behind these figures predate the hackathon. The prediction model, Sibyl integration, rule lifecycle, replay harness, live tail and coordination layer were built during it.

The live result is three observations against one counterparty, including a deliberately injected fault. It demonstrates that the decision depends on what was remembered. It is not a measurement of whether Priors hires better, and it is not comparable to the 18,360-job replay.

The condition vocabulary was chosen by a human who had already analysed this dataset. Individual rules are temporally clean, but that is a separate limitation from outcome leakage and it is worth stating plainly rather than pretending the feature set fell from the sky.
